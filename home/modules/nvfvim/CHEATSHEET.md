# Neovim keymap cheat sheet

<!-- markdownlint-disable MD013 -->

This is the complete reference for the maps owned by the Neovim configuration
in this repository. It also covers the useful buffer-local maps generated by
enabled plugins, including Neorg, Nvim-tree, Sentry, RoomPlan, flashcards,
testing, debugging, and presentation mode. Stock Vim motions and commands are
outside its scope; `Space fk` is the authoritative live view for the current
buffer.

## Notation and discovery

- `Space` is the global leader.
- `,` is the local leader, used mainly inside Neorg and Sentry buffers.
- `Ctrl-x`, `Alt-x`, and `Shift-x` mean hold that modifier while pressing `x`.
- A sequence such as `Space ff` means press Space, then `f`, then `f`.
- Unless a table says otherwise, a map is for Normal mode.
- Pause after `Space` to see the available groups in WhichKey.
- In the WhichKey popup, `Ctrl-d` and `Ctrl-u` scroll down and up.
- `Space fk` opens a live, searchable list of the maps Neovim currently has.
- `Space hc` opens this file from any project.

All primary IDE workflows use letters and ordinary modifiers. No primary
workflow depends on square brackets or similar awkward Swiss-keyboard keys.
Some plugin-native, buffer-local fallback keys use punctuation; they are listed
for completeness and are limited to those plugin windows.

### Tree-sitter text objects

Use these after an operator such as `d`, `c`, or `y`, or from Visual mode.

| Key | Selects |
| --- | --- |
| `af` / `if` | Around / inside function |
| `ac` / `ic` | Around / inside class |
| `aa` / `ia` | Around / inside parameter |
| `an` / `in` | Around parent syntax node / inside child syntax node |

Examples: `daf` deletes a function, `vif` selects a function body, and `cia`
changes the current argument.

## Formatting and linting

| Key | Action |
| --- | --- |
| `Space lf` | Format the current buffer with Conform; use LSP as fallback |
| `Space ll` | Run configured linters for the current buffer |

Formatting is deliberately not run on save. Prettier handles JavaScript,
TypeScript, Vue, Svelte, HTML, CSS, SCSS, JSON, YAML, Markdown, and Compose.
Language-specific formatters handle PHP, Python, QML, Nix, Lua, shell, TOML,
and GDScript. Linting does run after save where a linter is configured.
Language-server diagnostics remain automatic for languages without a separate
nvim-lint runner; `Space ll` only invokes the configured external linters.

| Key | Action when available |
| --- | --- |

In the DAP REPL, Normal `Enter` runs the first available action, `o` opens its
action menu, `G` jumps to the bottom, and `[[` / `]]` move to the previous /
next prompt. In Insert mode, `Up` / `Down` browse REPL history. `G` also jumps
to the bottom of the DAP Console. Floating DAP windows close with `q` or `Esc`.

- PHP listens for Xdebug on port 9003. Start the web or CLI request separately.
- Python launches the current file through debugpy.
- JavaScript and TypeScript can launch the current file through vscode-js-debug.
- Vue, Svelte, JavaScript, and TypeScript browser debugging asks for an
  application URL, defaulting to `http://localhost:5173`, and launches Chromium.
- Godot connects to the editor DAP server on port 6006; Godot must be open.

## Language coverage and service notes

LSP and Tree-sitter support is enabled for PHP, JavaScript, TypeScript, TSX,
Vue, Svelte, Twig, HTML, CSS, SCSS, JSON, YAML, XML, TOML, SQL, Bash, Fish,
Docker, Python, QML, Lua, Nix, Markdown, GDScript, Godot resources/shaders, and
Luau.

- Godot must be open for GDScript LSP on port 6005 and DAP on port 6006.
- QML uses Qt's `qmlls` and `qmlformat`.
- SQL completion becomes schema-aware after `sqls` is configured for the
  project database.
- `Space li` is the first check when navigation or completion is missing.
- `:checkhealth` gives the wider Neovim/plugin health report.
